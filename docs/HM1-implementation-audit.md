## 导航审计结论

- 原实现的角色标签集合正确，但没有把冻结根 `routeId` 纳入导航模型。
- 原 `directoryTab()` 将平台服务复用为组织管理，将成员和租户服务复用为连接记录，
  并把平台账号落入通用空状态。
- 原底栏以共享 `tab.key` 作为 `ForEach` 键。成员四栏和管理五栏都含
  `SERVICES/ME`，节点复用后保留旧 index，真机可复现错误跳转。
- 修复后平台、租户管理和成员底栏分别映射到冻结注册表中的根路由，页面根内容、
  详情返回和工作区 transition 均符合 HM-1 边界。
- 补充真机反馈修复：原验收只覆盖“账号”和“服务”分别可达，没有覆盖两者连续往返；
  现已拆分根 Builder，并将“账号 -> 服务 -> 账号”列为固定回归顺序。
- 平台账号、平台服务、租户服务和成员服务当前只保留互不混淆的根壳；其业务数据和
  操作分别属于 HM-2、HM-5 和 HM-7，本轮没有提前实现。
- HM-1 验收完成并冻结。本轮停止，不进入 HM-2。
